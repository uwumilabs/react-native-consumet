# Upgrading from 1.6.0

Every breaking or behaviour change since 1.6.0 that an app may need to handle, with a link to the details. Items marked **Breaking** need a code or data change in most apps. The others change what an app sees but need no change unless it relied on the old behaviour.

## Install and build

| Change                                                                                                                                                                                                                                              | What to do                                                                                         | Details                                                |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Breaking.** `react-native-get-random-values` is a peer dependency (`^1.8.0 \|\| ^2.0.0`) instead of a dependency.                                                                                                                                 | Add it to the app's own dependencies and rebuild the native app (`pod install` on iOS).            | [Installation](../../README.md#installation)           |
| The Android deobfuscator runs on `wang.harlon.quickjs:wrapper-android` 3.2.3, whose libraries are 16 KB page aligned, instead of `app.cash.quickjs:quickjs-android` 0.9.2. Very deep scripts now reject with `EvaluationError` instead of crashing. | Rebuild the Android app. Nothing else, unless the app pinned or excluded the old QuickJS artifact. | [`src/NativeConsumet.ts`](../../src/NativeConsumet.ts) |

## Episodes and metadata (`META`)

| Change                                                                                                                                                                                                                                                                                       | What to do                                                                                          | Details                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **Breaking.** `META.Anilist.fetchEpisodesListById` builds `uniqueId` as `${anilistId}$ep=${aniDbKey ?? number}` (AniDB numbering) instead of from TVDB numbering, and every episode has one. `number` stays the provider's number; TVDB numbers move to `tvdbNumber` and `absoluteNumber`.   | Rename stored progress keys once.                                                                   | [uniqueid.md](./uniqueid.md)                                                      |
| **Breaking.** `META.TMDB.fetchMediaInfo` keeps the TMDB id in `id`; the movie provider's media id is in the new `providerId`. With no provider match, the TMDB info is still returned, without `providerId` or episode ids.                                                                  | Pass `providerId`, not `id`, to the movie provider's `fetchEpisodeServers` / `fetchEpisodeSources`. | [tmdb-info.md](./tmdb-info.md)                                                    |
| **Breaking (types).** `IMovieEpisode.id` is optional, `IMovieInfo.duration` is `string \| number`, and `TMDB.fetchMediaInfo` returns `IMovieInfo` (no cast needed). TMDB episodes set `number`, seasons always have `episodes`, and `trailer` is unset when there's no video.                | Treat a missing episode `id` as "not on this provider".                                             | [tmdb-info.md](./tmdb-info.md#episode-season-and-info-types-match-the-data)       |
| `META.Anilist`, `META.TMDB` and `META.Myanimelist` throw `MetaError` (`source`, `status`, `cause`) instead of plain errors. The message is unchanged and `MetaError` extends `Error`.                                                                                                        | Optional: check `status === 429` for rate limits.                                                   | [Meta errors](../guides/meta.md#errors)                                           |
| AniList, TMDB and MAL requests time out after 15 s and retry a 429 or 5xx once. AniList no longer falls back to Anify (offline), so a 429 or 5xx ends in a `MetaError` instead of a misleading `TypeError`. ani.zip and filler lists are optional (5 s); episodes are returned without them. | None.                                                                                               | [Meta errors](../guides/meta.md#errors)                                           |
| `META.Anilist.fetchRecentEpisodes` is deprecated: it reads from Anify, which is offline, so it always fails.                                                                                                                                                                                 | Stop calling it.                                                                                    | [anilist.md](../providers/meta/anilist.md)                                        |
| `META.Anilist` and `META.Myanimelist` decide the ani.zip merge and combined sub/dub ids from the provider's declared `capabilities`, not its class. AniNeko now gets the ani.zip merge.                                                                                                      | None for registry providers; they declare capabilities.                                             | [Declaring Capabilities](../guides/adding-new-provider.md#declaring-capabilities) |

## Registry and provider loading

| Change                                                                                                                                                                                                                                                                                           | What to do                                                                                                                                                                         | Details                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Breaking.** `new ProviderManager(registry)` and `new ExtractorManager(registry)` throw a `RegistryError` for a missing or invalid registry, or one with a newer `schemaVersion`. They used to log the error and run with no entries.                                                           | Always pass a registry (`ExtensionRegistry` or a downloaded one), and catch `RegistryError` where a downloaded registry is loaded; `updateRequired` means the app needs an update. | [Validation](../extension-integration.md#validation)                                                  |
| Entries whose `minContextVersion` is newer than the library's `CONTEXT_VERSION` are listed but refused on every load path with `RegistryError` `INCOMPATIBLE_ENTRY` (`updateRequired: true`).                                                                                                    | Show such entries as needing an app update; `isCompatibleEntry(entry)` tells them apart.                                                                                           | [Incompatible entries](../extension-integration.md#incompatible-entries)                              |
| **Breaking.** `executeProviderCode` and `executeExtractorCode` throw `IntegrityError` when the code doesn't match the entry's `sha256`, or the entry has none. Extractor entries are now checked too.                                                                                            | Apps that cache code: re-download on `IntegrityError`. Custom registries: ship `sha256` for every entry.                                                                           | [Security Model](../security.md#1-sha-256-integrity-on-every-execution-path)                          |
| Registry `main` URLs point at immutable files, `registry/<kind>/<id>/<version>.js`, instead of `dist/` on `main`.                                                                                                                                                                                | None. Registries bundled with 1.6.0 and earlier still point into `dist/`; updating the library fixes them.                                                                         | [Security Model](../security.md#3-immutable-versioned-files)                                          |
| Providers loaded by `ProviderManager` run the registry version of their extractors (hash-checked, cached), falling back to the bundled one. An extractor in neither throws a clear error.                                                                                                        | None. To share the extractor cache with your own code, pass `{ extractorManager }`.                                                                                                | [ExtractorManager](../extension-integration.md#extractormanager)                                      |
| Factories receive the registry entry's `baseUrl`, and loaded providers are cached per id and `baseUrl`. `getAnimeProvider` / `getMovieProvider` / `loadExtension` accept `{ baseUrl }`.                                                                                                          | Custom registries: make `baseUrl` the provider's site.                                                                                                                             | [ProviderManager](../extension-integration.md#providermanager)                                        |
| Registry providers get the library's real enum values from `require('…/models')` (`TvType`, `MediaStatus`, `WatchListType`, `SubOrDub`). 1.6.0 handed extension code copies with other strings, such as `'tvseries'` and `'ongoing'`. Requiring a module the runtime doesn't provide now throws. | Compare results with the exported enums, not string literals.                                                                                                                      | [Step 4 of the provider guide](../guides/adding-new-provider.md#step-4-add-to-extension-registryjson) |
| VegaMovies, NetflixMirror, PrimeMirror and DisneyMirror are flagged `isSourceDirect`: their servers are not extractor names.                                                                                                                                                                     | Hand a server's URL to an extractor only when `haveMultiServers` is set and `isSourceDirect` isn't; otherwise call `fetchEpisodeSources` with the server name.                     | [Basic Extractor Usage](../extension-integration.md#basic-extractor-usage)                            |
| Code downloads abort after 30 s instead of hanging.                                                                                                                                                                                                                                              | None.                                                                                                                                                                              | [Security Model](../security.md#4-https-and-bounded-downloads)                                        |

## Native module

| Change                                                                                                                                                                                                                                                | What to do                                                                                       | Details                                                         |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| **Breaking.** On Android, WebView requests (`makeGetRequestWithWebView`, `makePostRequestWithWebView`, `getDdosGuardCookiesWithWebView`) reject with code `TIMEOUT` after 30 s. They used to resolve `status: 'timeout'` without `html` / `response`. | Catch the rejection where the app calls these directly.                                          | [`src/NativeConsumet.ts`](../../src/NativeConsumet.ts)          |
| On Android, failed sub-resources (images, scripts, iframes) no longer reject a WebView request; only the main document decides. On iOS, a navigation cancelled by a redirect no longer rejects.                                                       | None.                                                                                            | [`src/NativeConsumet.ts`](../../src/NativeConsumet.ts)          |
| On Android, `getDdosGuardCookiesWithWebView` resolves the Cookie header string, as on iOS, instead of `{ cookie }`.                                                                                                                                   | Read the string. Extension code for older apps should accept both.                               | [Native Module](../guides/adding-new-provider.md#native-module) |
| On iOS, `deobfuscateScript` rejects (`NetworkError`, `ParseError`, `EvaluationError`) instead of resolving `null`, and `bypassDdosGuard` rejects when no cookie comes back.                                                                           | Catch the rejection.                                                                             | [`src/NativeConsumet.ts`](../../src/NativeConsumet.ts)          |
| On iOS, the module's WebViews keep cookies in their own in-memory store: separate from the app's WebViews, cleared on restart, and filtered to the loaded URL. They used to share the app's default data store and return every cookie in it.         | Don't expect cookies set in the app's own WebViews to reach the module, or to survive a restart. | [Security Model](../security.md#6-native-module)                |
| On Android, WebView debugging is enabled only when the host app is debuggable, and cookie and header values are no longer logged.                                                                                                                     | None. Use a debuggable build to inspect the module's WebViews.                                   | [Security Model](../security.md#6-native-module)                |

## TypeScript types and exports

| Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | What to do                                                    | Details                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Breaking (types).** `getAnimeProvider` / `getMovieProvider` / `loadExtension` resolve `IAnimeProvider` / `IMovieProvider` instead of a provider class type, and take registry ids (`AnimeProviderId`, `MovieProviderId`, any string). `AnimeProvider` / `MovieProvider` are deprecated.                                                                                                                                                                                                                                                                        | Narrow or cast where the app calls provider-specific methods. | [ProviderManager](../extension-integration.md#providermanager)           |
| **Breaking (deep imports).** `src/providers/movies` no longer has named `VegaMovies` / `createVegaMovies` exports.                                                                                                                                                                                                                                                                                                                                                                                                                                               | Use `MOVIES.VegaMovies` and `MOVIES.createVegaMovies`.        |                                                                          |
| New root exports, none removed. Values: `MetaError`, `RegistryError`, `IntegrityError`, `validateRegistry`, `isCompatibleEntry`, `assertCompatibleEntry`, `verifyExtensionCode`, `CONTEXT_VERSION`, `REGISTRY_SCHEMA_VERSION`, `AnimeParser`, `MovieParser`, `WatchListType`, `FlixCloud`. Types: `IAnimeProvider`, `IMovieProvider`, `IMetaAnimeEpisode`, `ProviderCapabilities`, `AnimeProviderId`, `MovieProviderId`, `ProviderLoadOptions`, `ExtensionRegistryData`, `ProviderContext`, `ExtractorContext` and their config types, and the error code types. | Replace deep imports of these with the package root.          | [Some Helpful imports](../extension-integration.md#some-helpful-imports) |
