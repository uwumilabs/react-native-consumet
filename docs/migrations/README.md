# Upgrading from 1.6.0

Every breaking or behaviour change since 1.6.0 that an app may need to handle, with a link to the details. Items marked **Breaking** need a code or data change in most apps. The others change what an app sees but need no change unless it relied on the old behaviour.

## Since 3.0.1

| Change |
| ------ |
| **Breaking.** Library versions before 2.0.0 are not supported. `dist/` is no longer committed, so their registries' URLs (files under `dist/` on `main`) stop resolving, and registry bundles no longer carry the `exports` footer or the `../models` paths their loaders needed. Update the library. |
| **Breaking.** The extractors no provider used are removed: `AsianLoad`, `Filemoon`, `GogoCDN`, `MixDrop`, `Mp4Player`, `Mp4Upload`, `RapidCloud`, `StreamHub`, `StreamLare`, `StreamSB`, `StreamTape`, `VidMoly`, `VizCloud` and `Voe`, with their `StreamingServers` members and those of servers no extractor reads (`AsianLoad`, `GogoCDN`, `StreamSB`, `MixDrop`, `Mp4Upload`, `StreamTape`, `VizCloud`, `MyCloud`, `Filemoon`, `VidStreaming`, `BuiltIn`, `SmashyStream`, `StreamHub`, `VidMoly`, `Voe`, `Luffy`, `Multi`). Every remaining extractor is a function, `X(ctx).extract(url, ...)`, which resolves an `ISource`. |
| **Breaking (types).** `IVideoExtractor` is `{ extract }`: extractors no longer return `serverName` or `sources`. The new `ExtractorFactory` type is `(ctx: ExtractorContext) => IVideoExtractor`. `ExtractorContext.USER_AGENT` is always set. |
| **Breaking.** `ProviderManager.executeProviderCode(code, metadata, options?)` reads the factory name from `metadata.factoryName`; drop the second argument. |
| **Breaking.** Providers loaded through `ProviderManager` are instances of their category's base parser (`AnimeParser`, `MovieParser`, `MangaParser`, `LightNovelParser`), not of the bundled class (`instanceof ANIME.AnimeKai` is false for a registry-loaded AnimeKai). The `AnimeProvider`, `MovieProvider`, `animeProviders` and `movieProviders` types are removed; use `AnimeProviderId` / `MovieProviderId`. |
| **Breaking (types).** `ProviderContext` extends `ExtractorContext` and no longer has `extractorManager` (use `ProviderManager.getExtractorManager()`); `ProviderContextConfig` loses the `AnimeParser`, `MovieParser` and `MangaParser` overrides, and `ExtractorContextConfig` loses `extractors` (it only ever applied to provider contexts, where it stays). |
| An extractor that `ctx.extractors.X(ctx)` runs from the registry now runs with the context the provider passes, as the bundled one always did (it used the manager's). Called without a context, a bundled extractor uses the provider's context instead of the library's default one. |
| The library sends one default User-Agent (Chrome 91) everywhere; `defaultAxios` sent an older one (Chrome 83). |
| `ProviderManager.searchAcrossProviders` results carry the `error` of a provider that failed to load or search, next to its empty page. |
| A registry entry's code that can't be downloaded throws a `RegistryFetchError` with the HTTP `status` and `url` (the message is unchanged). |
| `ANIME.AniKoto` is no longer also exported as `AniWatchTv` from its module. |
| **Breaking.** `ANIME.AnimeKai`, `MOVIES.YFlix` and the `MegaUp` extractor are removed, with the `animekai` and `yflix` registry entries: their sites are gone (anikai.to has no address, yflix.to doesn't resolve). `MOVIES.MultiMovies` stays in the library, but its `multimovies` registry entry is removed (multimovies.center is a parked domain). |
| **Breaking.** Server names start with the extractor that reads them, `<extractor>-<label>`: AniNeko's are `vidhide-…`, `vivibebe-…` and `dood-…` (they had no prefix), and AnimePahe's are lower case (its `server` argument, ignored before, now picks a quality by prefix). Every anime and movie provider picks the server the same way: the first whose name starts with `server`, or the first server when none is given. AniKoto and AniNeko now throw when no server matches (they fell back to the first), with the error naming the available servers. |
| **Breaking.** The `GDFlix` extractor (no provider called it) is removed, with its registry entry and `StreamingServers.GDFlix`. Movie providers name their servers `<extractor>-<label>` too: HiMovies `megacloud-upcloud`; MultiMovies `streamwish-streamhg`, `vidhide-earnvids`, `streamwish-<host>`; VegaMovies `hubcloud-<label>`, `hubcloud`, `fastdl`, `filepress` (its sources' `server` too); the mirrors `netmirror-netflix`, `netmirror-prime-video`, `netmirror-disney`. Every movie provider plays its first server when none is asked for. `ANIME.Zoro.fetchGenres` returns genre names (`string[]`), as AniKoto's does. |
| VegaMovies plays Gofile links through the `Gofile` extractor (so its registry version applies). AniKoto lists no servers for an episode without a dub instead of the sub ones. AnimePahe passes Kwik's own headers and throws when an episode has no players. MultiMovies looks up seasons only for series (movies have `seasons` unset). VidHide unpacks its player script offline instead of through `NativeConsumet.deobfuscateScript`. |
| **Breaking.** `MOVIES.MultiMovies.fetchEpisodeSources` loses its `fileId` parameter. HiMovies list results have `seasons` (a number) instead of `season` (a string). MultiMovies popular and genre ids are page paths that `fetchMediaInfo` accepts (they were `post-<n>`). VegaMovies `fetchEpisodeServers` throws when a post id doesn't resolve to a link. |
| **Breaking.** `META.Anilist.fetchRecentEpisodes` is removed (it always failed), and so is Anilist's public `proxyConfig` property; `MetaErrorSource` loses `'anizip'` and `'filler'`, which nothing produced. `META.TMDB` and `META.Myanimelist` reject a failing provider call in `fetchEpisodeSources` / `fetchEpisodeServers` with a `MetaError` (`source: 'provider'`), as Anilist already did. |
| **Breaking.** `validateRegistry` (and so both managers) follows the publishing rules: ids are letters, digits and `-`; extractor names are letters and digits; versions are plain `x.y.z`. Every published registry already does. |
| When a master playlist puts the audio in separate renditions, MegaCloud, StreamWish and VidHide return only the master, as MegaPlay did (their variants play silent). A variant without a `RESOLUTION` is labelled `quality_N`. MegaCloud, StreamWish and MegaPlay throw when the master can't be fetched, and MegaCloud when an embed has expired, instead of returning no sources. Kwik and MegaCloud need the referer every provider already passes. |
| Site status text is read one way everywhere: unrecognised text is `MediaStatus.UNKNOWN` (AsuraScans, MangaHere and MangaKakalot left it out), and a page that shows no status leaves `status` unset. |
| Error messages: providers name themselves as `Name: message` (e.g. `MangaDex: …` instead of `[MangaDex] …`), errors are no longer re-thrown as plain `Error`s with only the message (the original error, e.g. an `AxiosError` with its status, reaches the app), and VidHide no longer says "Video not found". |
| **Breaking (data).** `META.Anilist.fetchAnimeInfo` keys episodes exactly as `fetchEpisodesListById` does: for providers that declare `aniZipEpisodes` (Zoro, AnimePahe, AniKoto, AniNeko), an episode ani.zip matches by air date or title to another AniDB number gets `${id}$ep=${aniDbKey}` instead of `${id}$ep=${number}` (e.g. a provider numbering a second cour 12–22 now gets `$ep=1…11`). Its episodes also carry ani.zip's title, description, image and TVDB numbers. | 
| **Breaking (types).** TMDB results, trending people, and AniList recommendation, relation and character-media nodes have string `id`s (some were numbers). |
| `META.Myanimelist` and `META.Anilist.Manga` return no episodes or chapters when no provider result is close to the title (they took the closest, or the first, result). `Anilist.Manga` asks MALSync once and only for providers it maps (MangaDex, MangaKakalot), and its info has `totalChapters` and `volumes`. `fetchRandomAnime` failures have `source: 'github'`. |
| `LIGHT_NOVELS.NovelUpdates.fetchChapterContent` rejects as unsupported (chapters are links to translators' sites), and a Cloudflare block fails with a clear error; ReadLightNovels lists the chapters of a novel without pagination. MangaDex errors keep the HTTP status and cause. MangaKakalot's `currentPage` is the page asked for. |
| TMDB: missing images are unset instead of `…/originalnull`, `similar` and `recommendations` give the year as `releaseDate`, `search` is typed `ISearch<IMovieResult>`. AniList: an unknown `totalEpisodes` is unset instead of `0` (or `NaN`). MAL: search results map `Movie`, `Special` and the other types. Anilist returns no episodes when no provider result is close, instead of loading an arbitrary one. |
| `MOVIES.MultiStream` is also available as the factory `MOVIES.createMultiStream(ctx, customBaseURL?, apiKey?)`; its recommendations carry ids `fetchMediaInfo` accepts, and `fetchEpisodeSources` scrapes the sites once. |
| Android `makePostRequest` honours a `Content-Type` header in any case (a lower-case one was replaced by JSON). |
| **Breaking.** The native methods `bypassDdosGuard` and `getDdosGuardCookiesWithWebView` are removed from `NativeConsumet` and from the `NativeConsumet` that contexts give registry code (nothing called them), with the `COOKIE_ERROR` and `ERROR` rejection codes. `deobfuscateScript` resolves `Promise<string>`. |
| WebView requests reject with `WEBVIEW_ERROR` when the hidden WebView's renderer dies (Android crashed the app; iOS never settled) or the loaded page can't be read (both resolved `status: 'success'` with an empty body). After a Cloudflare challenge, `url` and `cookies` are those of the page the challenge loads, not of the challenge page. iOS runs Synchrony with Android's 8 MB stack, so deep scripts no longer fail only on iOS, and iOS `makePostRequest` honours a `Content-Type` header in any case. |
| The `string-similarity` dependency is removed. |
